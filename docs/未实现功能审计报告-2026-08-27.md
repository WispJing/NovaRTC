## 一、后端未实现功能（NovaRTC）

### 1. 群聊管理：建群/解散/成员管理 —— 链路半成品（最大缺口）
- 下行链路齐全：表结构已建（`NovaRTC/novartc-flyway/src/main/resources/db/migration/V1.0.0__init.sql:69` `im_group_chat`、`:91` `im_group_member`），实体与 `ImGroupChatServiceImpl`/`ImGroupMemberServiceImpl` 已写，消息分发（`MessageHandler.java:49`、`LocalChatDispatchService.java:28`、`RocketMQChatDispatchService.java:121`）与会话列表（`ChatServiceImpl.chatList()`）均支持群聊。
- **写入入口为零**：全仓 grep `new ImGroupChat(` / `imGroupChatService.save` / `imGroupMemberService.save` 为 0 条（已核验）。客户端三个 Controller 无任何群端点；管理端 `AdminChatController.java:36-47` 仅有只读 `GET /groups`、`GET /groups/{id}/members`。
- 目前群数据只能靠开发种子 `db/migration-dev/R__init_data.sql:34-55` 硬编码 INSERT；生产环境不可能产生任何群。
- 缺失项：建群、解散群、邀请/移除成员、主动入群/退群的全部 API 与业务逻辑。

### 2. 自定义在线状态（忙碌/离开/隐身）
- `ChatMessage.proto:26-32` 声明 `PresenceStatus { ONLINE, OFFLINE, BUSY, AWAY, INVISIBLE }`。
- 服务端仅在连接/断开时自动派发 ONLINE/OFFLINE（`netty/UserChannelManager.java:54`、`:68`、`:121`）；Java 代码中 `BUSY`/`AWAY`/`INVISIBLE` 0 处使用，也无设置状态的 HTTP/WS 入口。
- 客户端发来的 `PRESENCE` 消息落入 `MessageHandler.java:52` 的 `default` 分支，仅打警告后丢弃。

### 3. 账号自助管理：改密码 / 改资料 / 头像
- `controller/LoginController.java:27-57` 只有 `login`/`logout`/`register`。
- `im_user.avatar_url` 字段存在（`entity/mysql/ImUser.java:51`）且会随 `ChatInfoVO`/`ContactVO` 下发，但全仓 `setAvatarUrl(` 调用为 0，注册时（`RegisterService.java:45-54`）不设置头像，头像永远为空。
- 无任何修改昵称/邮箱/密码的代码路径。

### 4. 删除好友（解除好友关系）
- `ContactController.java:31-66` 仅 `/list`、`/start`、`/request/list`、`/request/send`、`/request/handle` 五个端点（已核验），无删除好友。
- `ImFriendServiceImpl` 中无解除好友关系逻辑；好友申请仅支持以 `CANCELED` 状态撤回（`ImFriendRequestServiceImpl.java:129-135`）。

## 五、补齐优先级建议（供排期参考）
- **P0 群聊管理闭环**：建群/解散/邀请/移除/退群 API + 业务逻辑 + 前端 `GroupPanel` 对接（后端、前端最大缺口在此交汇）。
- **P1 账号自助**：改密码/改资料/头像上传入口（头像依赖文件上传，可先做资料与密码）。
- **P1 删除好友**：后端端点 + 前端入口，改动小、收益直接。
- **P2 自定义在线状态**：服务端处理客户端 `PRESENCE` 消息 + 前端状态设置入口。
- **P3 前端细节**：撤回/转发/引用/删除、置顶/免打扰、申请撤回、实时已读回执、验证码注册、忘记密码等（多项需后端配套接口，可逐项排期）。
