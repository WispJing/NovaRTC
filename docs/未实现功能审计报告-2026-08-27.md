# NovaRTC 后端与 Web 前端未实现功能审计报告

> 初次审计日期：2026-08-27
> 本次复核日期：2026-09-09
> 范围：`NovaRTC/`（Java 21 后端）、`NovaRTCWeb/`（Web 前端）。
> 按要求排除：文件上传、音视频通话不作为本报告的待办展开；仅记录其当前状态以及与其他功能的边界。
> 方法：全仓搜索 TODO/占位入口，逐项核对 Controller、Service、Protobuf、WebSocket、前端 Store 和页面调用链。
> 口径：代码存在只代表“静态已实现”；未在本次复核中实际运行的链路会明确标为“运行时未复验”。文中路径均相对于工作区根目录 `NovaRTC-Platform/`。

## 一、本次复核结论

与 2026-08-27 初次审计相比，以下能力已经补齐或取得实质进展：

- **已补齐**：头像上传与更新、图片/视频/语音/普通文件消息收发、消息撤回、单聊好友资料卡。
- **基本补齐**：已读回执。接收方通过 `/api/chat/read` 落库，发送方通过历史消息刷新/轮询获得“已读/未读”状态；尚未实现 WebSocket 主动推送回执。
- **桌面端已实现、Web 端受限**：录音和截图。Tauri 端有录音、截图、预览、上传和发送链路；纯 Web 端语音采用选择 MP3 文件，截图仍提示仅桌面端支持。
- **仍是主要缺口**：群聊创建与成员管理、账号资料/密码自助修改、删除好友、自定义在线状态、后台管理页、文件中心、会话置顶/免打扰、消息转发/引用/删除、好友申请主动撤回、验证码/找回密码/扫码登录。

本次在 `NovaRTCWeb/src` 中静态检出 `pendingFeature()` **15 个调用点，分布于 9 个业务文件**。部分调用点由动态菜单或操作类型复用，因此调用点数量不等于未实现功能数量。

## 二、后端仍未实现或部分实现的功能（NovaRTC）

### 1. 群聊管理：建群/解散/成员管理 —— 链路仍未闭环（P0）

- 群表、群成员表、实体、查询 Service、消息持久化/分发、会话列表和成员关系缓存均已存在。
- 用户侧 Controller 仍没有群聊管理端点；管理端 `AdminChatController` 只有群列表和成员列表等只读查询。
- `ImGroupChatServiceImpl`、`ImGroupMemberServiceImpl` 提供基础持久化能力，但未发现创建群、解散群、邀请/移除成员、主动入群/退群的业务调用入口。
- 开发数据仍由 `NovaRTC/novartc-flyway/src/main/resources/db/migration-dev/R__init_data.sql` 直接写入 `im_group_chat`、`im_group_member`；不能替代生产写入链路。

结论：群聊“已有数据可展示、可发消息”，但生产环境不能由用户创建和维护群，仍是最大功能缺口。

### 2. 自定义在线状态（忙碌/离开/隐身）—— 未实现（P2）

- `ChatMessage.proto` 仍声明 `ONLINE/OFFLINE/BUSY/AWAY/INVISIBLE` 五种状态。
- 服务端 `UserChannelManager` 只在连接/断开时派发 ONLINE/OFFLINE。
- `MessageHandler` 的业务分支只接收文本、图片、视频、语音、文件和图文消息；客户端上行 `PRESENCE` 仍会进入 unsupported/default 分支。
- 前端也只把状态折算为在线/离线，没有设置本人状态的入口。

### 3. 账号自助管理：头像已实现，资料/密码仍未实现（P1）

- **已实现**：`POST /api/file/upload` 支持 `bizType=avatar`，`POST /api/user/update-avatar` 校验当前用户、文件归属和业务类型后更新头像对象键；登录、联系人、会话和管理端展示会解析为 MinIO URL。
- **已实现**：Web 设置抽屉可选择图片、上传头像、提交 `fileId` 并同步本地用户信息。
- **仍缺失**：修改昵称、邮箱等资料的用户 API/Service 与前端表单。
- **仍缺失**：修改密码、忘记密码和密码找回链路。

### 4. 删除好友（解除好友关系）—— 未实现（P1）

- `ContactController` 仍只有联系人列表、发起单聊、好友申请列表、发送申请、处理申请五类端点。
- 未发现解除好友关系的后端业务逻辑或 Web 操作入口。
- 好友申请的 `CANCELED` 是“撤回申请”状态，不等于删除已经建立的好友关系。

### 5. 已读回执 —— 基本实现，实时推送未实现（P3）

- **已实现**：`POST /api/chat/read` 校验会话访问权并批量写入 `IMReadStatus`。
- **已实现**：历史接口按阅读方返回消息 `read` 状态，Web 在打开会话、页面重新可见和定时轮询时刷新发送方的“已读/未读”展示。
- **未实现**：`ReadStatus` 虽在 proto 中定义，但没有挂入 `MsgBody.content`，也没有 WebSocket 回执事件。因此当前是拉取式回执，不是即时推送。

### 6. 消息撤回 —— 已实现，不再列为缺口

- `POST /api/chat/recall` 校验消息归属和 2 分钟时限，将消息标记为已撤回，并通过 `RECALL` 消息通知对端。
- 图片/视频/语音/文件消息撤回时会同步删除关联 MinIO 对象和 `im_file` 记录；历史消息以撤回占位返回。

### 已实现，不再列为缺口

- **单聊好友资料卡**：聊天头部用户按钮会打开资料卡，展示会话已有的头像、编号、在线状态和最近消息时间；它是只读卡片，不包含资料编辑能力。
- **图片与附件消息**：编辑器可上传并发送图片、MP4、普通文件和音频；Store、Protobuf 编解码、服务端持久化/分发及气泡展示均覆盖 IMAGE/VIDEO/AUDIO/FILE。
- **消息撤回**：自己的普通消息在 2 分钟内显示撤回按钮，成功后本地和对端替换为撤回占位。

## 四、排除项状态（仅标注，不展开）

- **文件上传**：已实现统一 `POST /api/file/upload` + MinIO + `im_file` 记录链路。聊天图片、文件和头像已有历史运行证据；视频、音频、Tauri 截图/录音在本次复核中仅确认代码链路，未重新执行端到端测试。
- **音视频通话**：仍未实现。`NovaRTC/docs/1v1音视频通话实现方案.md` 仍是设计方案，proto 无通话信令类型，聊天头部语音/视频通话按钮仍调用 `pendingFeature()`。

## 五、已核查、确认不是缺口（避免误报）

- `@Description TODO` 仍只是若干实体类的 Javadoc 模板文字，不代表对应业务未实现。
- proto 的 AUTH、SYSTEM、FRIEND_REQUEST 以及普通消息、附件消息、RECALL 均已有处理链路。
- 风控、管理端操作日志/登录日志、定时任务平台等能力不应因 Web `Manage.vue` 仍占位而误判为后端未实现；该缺口是 NovaRTCWeb 未对接管理体系。
- 前端“文件中心未实现”与“聊天文件上传/收发已实现”是两个独立结论。

## 六、建议补齐优先级

- **P0 群聊管理闭环**：建群、解散、邀请、移除、退群 API + 业务逻辑 + `GroupPanel` 对接，并补充权限、并发和缓存一致性测试。
- **P1 账号自助**：资料修改、修改密码、找回密码；头像链路不再纳入此待办。
- **P1 删除好友**：后端解除关系端点、会话影响规则和前端确认入口。
- **P2 自定义在线状态**：定义多端状态合并规则，再补服务端 PRESENCE 上行处理与前端设置入口。
- **P2 文件中心**：明确它是“聊天附件索引/检索”还是“个人文件盘”，再设计查询、权限和删除规则。
- **P3 交互细节**：会话置顶/免打扰、好友申请撤回、消息转发/引用/删除、推送式已读回执、验证码注册、扫码登录、消息管理器。

## 七、验证说明

- 本次更新完成了静态代码复核和前后端调用链对照，没有启动 Java、Web、MySQL、MongoDB、RocketMQ 或 MinIO。
- 因此“已实现”默认表示代码链路已存在；涉及网络、对象存储、桌面插件、权限、消息队列和多端同步的能力，仍应在目标环境执行集成测试后再标记为运行时验收通过。
