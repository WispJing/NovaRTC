# NovaRTC 1v1 音视频通话实现方案

> 状态：设计稿（未实施）。本文档为后续开发依据，实施时以本文件为准。

## 1. 目标与范围

为好友间增加 1v1 音视频通话。已确认的设计决策：

- **范围**：1v1 音视频通话（MVP），不做多人通话、不做录制。
- **媒体架构**：P2P WebRTC 直连，服务器只转发信令、不碰媒体；唯一新增的 Docker 服务是 **coturn**（STUN/TURN，解决 NAT 穿透），加入现有 `NovaRTC/docker/docker-compose.yml`，满足「Docker 可部署」的运维要求。
- **客户端**：WPF 用 **WebView2** 承载通话页面，直接使用浏览器级 WebRTC（采集/渲染/回声消除/编解码全部现成），C# 与 JS 通过 postMessage 桥接信令。
- **信令**：完全复用现有 Netty IM 长连接（`ws://…:9688/ws` + protobuf `MsgBody`），新增 `CALL` 消息类型，复用单聊定向分发链路。

```
WPF A (WebView2/JS)  <═══ 媒体 P2P (ICE/STUN/TURN) ═══>  WPF B (WebView2/JS)
   │                                                         │
   └── 信令 (protobuf CallSignal, 现有 /ws 长连接) ──> Netty 服务端(纯转发) ──┘
                     coturn (docker-compose 新增, 3478 + UDP relay)
```

## 2. 现状关键事实（已核实）

- 后端入口 `netty/NovaRTCServer.java`，`MessageHandler.channelRead0` 按 `MessageType` 分发（`MessageHandler.java:42-53`）；聊天消息走风控 → 好友校验 → 持久化 → `ChatDispatchService.dispatch`。
- 分发已有单机/多实例双实现：`LocalChatDispatchService`（按 `singleChatInfo.user2Id` 直投）与 `RocketMQChatDispatchService`（Redis 路由表 + Tag 投递），**通话信令可直接复用 `dispatch`，零新增分发代码**（通话信令不持久化、不过风控）。
- proto 双端共享：后端 `novartc-server/.../proto/ChatMessage.proto` + 手工 `protoc` 生成并提交的 `ChatMessage.java`（pom 无 protobuf-maven-plugin，保持该约定）；客户端 `NovaRTC.Protocol` 用 Grpc.Tools 编译期自动生成 C#。
- 客户端 `Services/MessageService.cs` 按 `ContentCase` 分发消息；`MainViewModel` 单 ViewModel；csproj 目前无 WebView2 依赖。
- 全仓库目前无任何音视频相关代码（WebRTC/SDP/STUN/媒体），本方案为全新功能。

## 3. 实施步骤

### 第 1 步：协议扩展（两端 proto 同步）

同步修改两处（内容必须一致）：

- `NovaRTC/novartc-server/src/main/java/io/github/xiaotang/novartc/server/proto/ChatMessage.proto`
- `NovaRTCClient/NovaRTC.Protocol/ChatMessage.proto`

新增内容：

1. `MessageType` 增加 `CALL = 12;`
2. 新增枚举与消息：

```proto
enum CallEventType {
  CALL_INVITE = 0;       // 发起呼叫
  CALL_ACCEPT = 1;       // 接听
  CALL_REJECT = 2;       // 拒接
  CALL_CANCEL = 3;       // 接听前取消
  CALL_BUSY = 4;         // 忙线
  CALL_HANGUP = 5;       // 挂断
  CALL_OFFER = 6;        // SDP offer
  CALL_ANSWER = 7;       // SDP answer
  CALL_ICE_CANDIDATE = 8;
}

enum CallMediaType {
  CALL_AUDIO = 0;
  CALL_AUDIO_VIDEO = 1;
}

message CallSignal {
  string call_id = 1;
  CallEventType event_type = 2;
  CallMediaType media_type = 3;
  string sdp = 4;               // OFFER/ANSWER 用
  string candidate = 5;         // ICE 用
  int32 sdp_mline_index = 6;
  string sdp_mid = 7;
  string reason = 8;            // 拒接/结束原因，如 busy、timeout、offline
  int64 timestamp = 9;
}
```

3. `MsgBody.oneof content` 增加 `CallSignal call_signal = 16;`
4. 通话信令复用 `single_chat_info` 标识对端（`user2_id` = 对端），这样后端路由完全复用单聊路径；主叫方在 `sender` 中。

随后用 `protoc`（需 ≥ 4.32，与 `protobuf-java 4.32.0` 匹配）重新生成后端 `ChatMessage.java` 并提交（沿用现有手工生成约定；执行时先 `which protoc` 确认，缺失则先安装）。客户端 C# 由 Grpc.Tools 编译期自动生成，无需手工操作。

### 第 2 步：后端信令转发

- `netty/MessageHandler.java`：`switch` 增加 `case CALL -> imMessageWorkerPool.submit(userId, () -> handleCallSignal(ctx, msgBody, userId));`
- 新增 `service/CallSignalService.java` + `service/impl/CallSignalServiceImpl.java`（遵循现有 service/impl 约定）：
  - 校验 `call_signal` 与 `single_chat_info` 完整性、对端非空；
  - 好友校验：复用 `UserRelationCacheService.isFriend`；
  - `CALL_INVITE`：用 `UserChannelManager.isOnline` 判断对端在线，离线则给主叫回一条 `CALL_CANCEL`（reason=`offline`），避免主叫空等 30 秒；
  - 其余事件：直接转发对端；
  - **不持久化、不过风控**，直接 `chatDispatchService.dispatch(msgBody)`（单机/RocketMQ 双模式自动生效）。
- `config/`：新增 `CallProperties`（前缀 `call.turn`），配置项 `stun-urls`、`turn-url`、`username`、`credential`；在 `application-dev.yml` 增加默认值（指向本机 coturn；凭据仅开发值，遵守不提交真实密钥约定）。
- 新增 `controller/CallController.java`：`GET /api/call/ice-servers` 返回 ICE 服务器列表（含 TURN 凭据），供客户端注入 WebView2。登录态鉴权沿用现有 `Interceptor` 机制（实施时确认其拦截路径并纳入）。
- 单元测试：`CallSignalServiceImplTest`（`src/test/java`，命名 `*Test`），覆盖：对端离线回退、好友校验拒绝、事件转发目标解析。

### 第 3 步：coturn 加入 Docker Compose

`NovaRTC/docker/docker-compose.yml` 的 `services` 下新增：

```yaml
coturn:
  image: coturn/coturn:4.6.2
  container_name: coturn
  restart: unless-stopped
  networks:
    - novartc-net
  ports:
    - "3478:3478"
    - "3478:3478/udp"
    - "50000-50100:50000-50100/udp"   # TURN 中继端口段
  command: >
    -n --realm=novartc --no-cli
    --listening-port=3478
    --min-port=50000 --max-port=50100
    --user=novartc:novartc-turn-dev
    --log-file=stdout
```

静态凭据为开发默认值；生产建议后续升级为 REST 临时凭据（本期不做）。

### 第 4 步：客户端信令与状态机

- `NovaRTC.UI.csproj`：新增 `Microsoft.Web.WebView2` NuGet 包；新增 `Assets/call/`（index.html、call.js、call.css）为 `Content` + `CopyToOutputDirectory=PreserveNewest`。
- `Services/MessageService.cs`：`HandleMessage` 增加 `CallSignal` 分支，触发 `OnCallSignal` 事件；新增 `SendCallSignal(...)` 发送方法（构造 `MsgBody` + `single_chat_info`）。
- 新增 `Services/CallService.cs`（通话状态机，核心类）：
  - 状态：`Idle / OutgoingRinging / IncomingRinging / InCall`；
  - 主叫流程：发起 → 发 `CALL_INVITE` → 30 秒未接听自动 `CALL_CANCEL`(timeout)；
  - 被叫流程：收到 INVITE → 触发来电事件 → 接听发 `CALL_ACCEPT` / 拒接发 `CALL_REJECT`（忙线时用 `CALL_BUSY`）；
  - 通话中：转发 SDP/ICE 事件到通话窗口；收到 `CALL_HANGUP` 结束并清理；
  - 同一时刻仅允许一通通话，冲突回 `CALL_BUSY`。

### 第 5 步：通话窗口与 WebRTC 页面

- 新增 `Views/CallWindow.xaml(.cs)`：承载 `WebView2`，工具栏含麦克风开关、摄像头开关、挂断、通话计时；加载本地 `Assets/call/index.html`。
- `Assets/call/call.js`（标准浏览器 WebRTC，约 200 行）：
  - `getUserMedia({audio:true, video:true})` 采集，本地视频渲染；
  - `RTCPeerConnection`，`iceServers` 由 C# 初始化时注入（`/api/call/ice-servers` 结果）；
  - `onicecandidate` → `window.chrome.webview.postMessage` 发给 C#；
  - 暴露给 C# 的入口（`ExecuteScriptAsync` 调用）：`createOffer()`、`handleOffer(sdp)`、`handleAnswer(sdp)`、`addIceCandidate(json)`、`toggleMic(bool)`、`toggleCamera(bool)`、`hangup()`；
  - 对端流到达 → 渲染远端视频；连接状态（connecting/connected/failed/disconnected）回传 C# 显示。
- 桥接方向：C#→JS 用 `CoreWebView2.ExecuteScriptAsync`；JS→C# 用 `WebMessageReceived`（JSON）。
- `Views/MainWindow.xaml`：单聊会话头部/联系人右键菜单增加「音视频通话」按钮（仅好友单聊可用），点击调用 `CallService.StartCall`；收到来电事件弹来电确认（复用现有窗口风格，新建轻量来电窗口或在主窗口顶部弹层，实施时按现有 UI 风格选简单者）。

### 第 6 步：验证

1. 后端编译：`cd NovaRTC && mvn -pl novartc-server -am compile`；测试：`mvn -pl novartc-server test`。
2. coturn：`cd NovaRTC && docker compose -f docker/docker-compose.yml up -d coturn`，`docker logs coturn` 确认启动，用 Trickle-ICE 测试页验证 3478 可达。
3. 客户端编译：`dotnet build NovaRTCClient/NovaRTCClient.sln`（需在 Windows 上，WPF 无法在 Linux 环境运行）。
4. 手动联调（两台机器或同机两账号）：
   - 发起 → 接听 → 双向音视频 → 挂断；
   - 拒接、取消、30 秒超时、对端离线呼叫；
   - 麦克风/摄像头开关；
   - 局域网直连与经 TURN 中继两种场景（可临时禁直连验证）。

## 5. 说明与边界

- **验证边界**：Linux 开发机可验证后端编译/测试与 coturn；WPF 客户端（WebView2）必须在 Windows 机器上编译运行。
- **多实例**：信令复用现有 `ChatDispatchService` 双实现，`rocketmq.enabled=true` 时经路由表投递，无需额外开发。
- **暂不做**（后续可选）：通话记录落库、REST 临时 TURN 凭据、多人通话（需 SFU）、通话质量统计。
